## AI時代の重要な質問テンプレート
<details>

  ### 基本の思考順序

  **目的 → 構造 → 選択肢 → 判断基準 → リスク**

  <br>
  
  ### 1. 全体像をつかむ
  
  * この分野を理解するために必要な概念を5個に分けて
  * これは何の問題を解決するもの？
  * 全体構造を初心者向けに説明して
  
  ### 2. 深く理解する
  
  * なぜそうなる？
  * 従来の方法ではなぜダメ？
  * 内部ではどう動いている？
  
  ### 3. 判断する
  
  * AとBなら、どんな条件で使い分ける？
  * どんな場合は使わない方がいい？
  * この選択のトレードオフは？
  * 私の条件なら、どれを選ぶべき？理由も教えて
  
  ### 4. AIの回答を疑う
  
  * この回答を信用すると危険なポイントを3つ挙げて
  * この回答が間違っている可能性は？
  * この回答の前提条件は？
  * 抜けている観点は？
  * 別の専門家ならどう反論する？
  
  ### 5. 自分の理解を検証する
  
  * 私の理解の間違いを指摘して
  * 私の説明で抜けている部分は？
  * 私の判断を厳しくレビューして
  * 重要なのに私が聞いていないことは？
  
  ### 6. 失敗を先に知る
  
  * 典型的な失敗パターンは？
  * どこで壊れやすい？
  * 本番運用すると何が問題になりやすい？
  * 最悪のケースは？
  
</details>

## このPRを、私が「自分で実装内容を説明できる状態」になるように解説してください。

<details>
  
  以下の順番で説明してください。
  
  1. **このPRの目的**
  
     * 何を解決するPRなのか
     * 変更前はどうだったのか
     * 変更後どうなるのか
  
  2. **変更の全体像**
  
     * 変更されたファイルを役割ごとに分類
     * 各ファイルを「なぜ変更したか」一言で説明
     * 重要度を ★★★ / ★★ / ★ で付ける
  
  3. **処理フロー**

     ユーザー操作やAPI呼び出しを起点に、

     ```
     入力
     ↓
     Controller / API
     ↓
     Service / Model
     ↓
     DB / 外部API
     ↓
     Response
     ```
     
     のように、実際の処理順で説明してください。
  
  4. **重要なコードだけ詳しく説明**

     すべての行を説明するのではなく、
     「このPRを理解するために重要なコード」に絞ってください。
  
     各コードについて、
  
     * このコードは何をしているか
     * なぜ必要か
     * 無かったら何が起こるか
       を説明してください。
  
  5. **設計上のポイント**
  
     * なぜこの実装方法なのか
     * 他に考えられる方法
     * この方法を選ぶメリット・デメリット
  
  6. **注意点・リスク**
  
     * バグになりそうな場所
     * 境界値
     * データ不整合
     * N+1 / パフォーマンス
     * トランザクション
     * 例外処理
     * セキュリティ
       などを確認してください。
  
  7. **最後に超要約**

     「このPRでは、〇〇するために、△△を変更し、□□という流れで処理する」
     という形で3〜5行にまとめてください。
  
  専門用語を使う場合は、その場で短く意味も説明してください。
  コードを上から順番に説明するのではなく、まず全体像を理解できる説明を優先してください。
  
</details>
